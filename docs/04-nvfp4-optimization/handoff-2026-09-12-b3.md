## 2. A/B 对照证据（今天最关键的结论）

同一 prompt `Hello, my name is`，max_tokens=40，temperature=0：

| 配置 | 输出 | 判定 |
|---|---|---|
| 基线 + MTP | "Daniel. I am a 24-year-old male. I have been experiencing a persistent cough for the past 3 weeks. I have no fever, no shortness of breath, and no chest" | ✅ 完美 |
| 基线 + 无MTP | 同上（**连跑两次逐字一致，确定性确认**） | ✅ 完美 |
| **改后 + 无MTP** | "I'm a 24-year-old male, and I've been experiencing a persistent cough for the past two weeks. I'm not a smoker, a non-smoker, and I common cold symptoms" | ⚠️ 大体通顺，结尾破碎 |
| **改后 + MTP** | "I'm a student student student..." 重复循环，MTP acceptance 0.36→0.048→0.35 剧烈波动 | ❌ 坏 |

**结论**：
1. 实锤是我的 kernel 改动（基线两组完美，改后两组退化）
2. M=1 核心大体对（无 MTP 输出通顺不是乱码）→ y 映射数学已逐行核对 5 遍是对的
3. 有细微数值 bug（temperature=0 下基线/改后本应逐字一致，实际不同）
4. MTP 把小 bug 放大成重复循环（draft 模型走我的 kernel，产生"看似合理但实际错"的草稿 token，部分被接受污染上下文）

**bug 嫌疑排序**（未验证）：
- **A. R=8 多行归约/写回路径**（最可疑）：NVFP4 之前从没跑过 rows_per_block>1，这段代码首次被激活；无 MTP 时"大体对+局部错"与此吻合（R=8 时每个 block 处理 8 行，归约路径对每行都生效）
- B. y preload 的 ds/scale 处理细节（映射已核对对，但 ds 低半/高半的取舍可能有细微差）
- C. standalone 与生产路径不一致（见 §5 开放问题）

## 5. 开放问题（接手先查）

1. **standalone 与生产路径是否一致**：standalone 里 B 是 F32（`ggml_cuda_should_fuse_mul_mat_vec_q` 要求 `src1->type == F32`，ggml-cuda.cu:1878），但 kernel 是 `vec_dot_nvfp4_q8_1`（读 Q8_1 输入）。需确认 F32 输入在 `ggml_cuda_mul_mat_vec_q` 里是否先 dequant 成 Q8_1 再进同一 kernel——如果 standalone 和生产的 y 类型/路径不同，+44% 测量和 M=1 正确性测试可能测的不是同一条路径。**查 `ggml_cuda_mul_mat_vec_q` 的 src1 类型处理分支即可，30 分钟，不用重编。**
2. **bug 在 R=8 归约还是 y preload**：见 §6 步骤 3 的 env var 二分法。

## 7. 踩坑清单（今天下午新增，重点）

1. **Tegra GPU 通道拖死**（最贵的一坑，吃掉 ~2 小时）：任何 kernel 崩溃（非对齐 int 读 → 向量化 16B 对齐 load 非法访问）会拖住整个 nvgpu 通道，后续所有 GPU 进程卡 D 状态 `rt_mutex_slowlock_locked`，kill -9 无效，**只能重启板子**。microbench 崩了先查代码别急着重启。
2. **自定义量化结构体必须与 ggml-common.h 逐字段核对**：microbench4 的 `block_q8_1` 误用 2 字节 d（真实是 4B `ggml_half2`）→ qs 落到 offset 2 非 4B 对齐 → `(const int*)qs` 崩溃。非对齐字段禁止 `(const int*)` 强转，用逐字节构造（`get_int_b4` 模式）。
3. **37 分钟/次 qemu 交叉编译是最大时间黑洞**：改参数类实验必须做成运行时 env var，一次编译测多组配置；改代码前先用 1 分钟 standalone 验证假设。
4. **standalone 必须测正确性（CPU 参考对比），不能只测速度**：今天 +44% 速度是真的，但正确性 bug 被漏到全模型阶段才暴露，白等一次 37 分钟编译。
5. **建图 API**：`ggml_new_graph` 不自动收集节点；`ggml_graph_add_node` 不设 COMPUTE flag（0x10）→ node 被 ggml-cuda.cu:4402 静默跳过（假 0.001ms）；必须 `ggml_build_forward_expand(gf, C)`；内存用 `ggml_backend_alloc_ctx_tensors(ctx, backend)`。
6. **CUDA 计时**：CUDA backend 用 `cudaStreamPerThread`，cudaEvent 在 default stream 上不同步 → 假数据；用 host 时钟 + `cudaDeviceSynchronize`。
7. **交叉编译链接**：`--allow-shlib-undefined` 须经 `-Wl,`；`-x none` 会误作用 .cu；分两步 nvcc .cu→.o 再 g++ 链接；需 `-lcuda -lgomp`。
8. **板上启动 server**：必须 `(setsid bash -c '... exec ./llama-server ...' > log 2>&1 < /dev/null &)` 子 shell 包裹，否则 ssh 断开把子进程带走。
9. **板子重启后**：ssh 起得晚（DriveOS 慢）须等；重启后必查 hugepages（23552 全 Free）、温度、`/dev/nvgpu/igpu-0000:01:00.0/power`。
10. **GPU 刚重启时钟没拉满**：第一次跑 standalone 可能偏低（今天 ffn_down 假回退），COLD 数据跑两次取一致值。
