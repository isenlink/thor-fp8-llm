# Two-board comparison: same goal, two implementations (board3 vs board4)

**中文标题：两台同型板的对照 —— 同一个目标，两套实现**

> 日期：2026-09-16 · 来源：board3 本机实测记录 + board4 书面自述（后者已经 board4 本人实测校验）
> 目标一致：在 DRIVE Thor 板上部署 Agent，**全量落非易失分区、脏断电后能自动回来**

## 一、总览对照

| 维度 | board3（本机实测） | board4（本人实测校验） |
|---|---|---|
| 系统 | DriveOS 7.0.3 / 内核 6.1.119-rt / 12 核 / 58 GiB | DriveOS 7.0.3 / Ubuntu 24.04.1 / 内核 6.1.119-rt45 / 12 核 / 58 G |
| 安装路径 | **路径 B 离线轮子**（本机下 aarch64 轮子 → 传板 → 离线装） | **路径 A 板端自举**（板载 venv + 镜像取 wheel） |
| 安装位置 | `/brand_data/hermes/` | `/brand_data/ai_workspace/hermes/` |
| overlay 薄壳 | systemd 单元母本 + `/etc/profile.d/99-*.sh` | `/etc/profile.d` 注环境 + 持久区 wrapper |
| 自启挂点 | **板端**恢复脚本末尾钩子（改出厂件，已备份原文件、幂等、fail-open） | **宿主侧**守护的恢复命令表（不碰板端共用件，多一跳） |
| DNS 修法 | 重写 `/etc/resolv.conf` + 解析器 drop-in，随恢复脚本重建 | 解析器跟随默认路由 + `timeout:2 attempts:2`，母本在持久区 |
| 默认模型 | 外网 DeepSeek（管理员指定） | 外网 DeepSeek（管理员指定） |
| 回落链 | 板本机 `llama-server`（`qwen3.8-27b`，ctx 262144） | 内网 `New API` 的 code 别名 → `交接主机` 的 `qwen3.8-27b` |
| 端到端 | ✅ 已验：`hermes chat` 2–3 s（修 DNS 后）；此前 3 min 11 s | ✅ 已验：首轮 28.4 s（含初始化）/ 次轮 3.9 s，`errors.log` 空 |
| 持久化验收 | L2 合并验证：破坏 4 类薄壳 → 恢复 → 全项复验通过 | 持久化母本就绪；宿主侧钩子按计划挂载 |

## 二、共同结论（两套实现都验证到的部分）

1. **只有数据分区扛得住脏断电**；overlay 侧的薄壳必须可由恢复脚本重建（DNS、环境变量、服务单元、大页池）。
2. **官方安装脚本在板端跑不了**（无 `curl`/`git`/**`apt`**/编译器）；两条替代路径都成立，选择取决于板端能否直连包索引。
3. **出厂解析器不可用是共同故障源**，且都表现为"看起来像网络慢/模型慢"。
   唯一正解：**解析器跟随默认路由**（母本放持久区、恢复时写回）；`/etc/hosts` 只作临时手段。
4. **只读根上放不了 shim**（`/usr/local/bin` 加 `sudo` 也不可写）⇒ 环境变量一律走 `/etc/profile.d`。
5. **自启挂点没有"免费"的选择**：改出厂件（一跳、但刷板即丢）vs 挂宿主侧（不碰共用件、但多一跳且守护自身要先活着）。
   ⇒ 工程上应**两条并存**：板端为主，宿主侧兜底。

## 三、各自独有的事实（对方纠正/补充，已并入正文）

| 事实 | 归属 | 意义 |
|---|---|---|
| 板上**没有 `apt`**（`apt-get: command not found`） | board4 实测 | 排除"用 apt 装 venv/pip"这条不存在的路 |
| pip 自举时镜像索引按**字符串**排序会选到 `pip 9.0.3`（连自身都装不上） | board4 实测 | 必须按版本号数值排序；改 `26.2.1` 后一次通过 |
| 出厂解析器落在**车载内网 VLAN 路由**上、默认路由在另一个网口 | board4 实测 | 定性从"解析慢"纠正为"根本到不了"（6/6 域名超时，其余 3 个公共解析器正常） |
| 只读根实测（`touch /usr/local/bin/x` → `Read-only file system`，`sudo` 同样） | board3 实测 | 推翻"往 /usr/local/bin 放 shim"的做法 |
| Agent 要求模型窗口 ≥64K、`llama-server` 必须 `--cache-ram 512` | board3 实测 | **仅在以板本机服务为后端时适用**（云端 API 后端不会遇到） |
| 兜底守护日志落 tmpfs ⇒ 宿主重启后静默归零 8 h 49 min | board4 事故 | **实现缺陷**（非路线缺陷）；兜底进程必须自带存活证明 |

## 四、择优结论（本轮）

- **安装**：路径 A 优先（更短、移动件更少），路径 B 作为无出网兜底；两条命令都留在文档里。
- **薄壳**：`/etc/profile.d` + 持久区 wrapper（board4 方案）。
- **自启**：板端钩子为主 + 宿主侧兜底（`fail-open`、幂等、出厂件风险写进文档）。
- **DNS**：统一规则——解析器跟随默认路由 + `timeout:2 attempts:2` + 母本在持久区 + 恢复时写回 + 禁长期 hosts 补丁。
- **模型**：各自按需；文档只写"默认/辅助/回落"的构成与取舍（外网 API 的能力与成本 vs 内网端点的可达性；
  注意内网端点"外网断时仍可用"≠"更稳"，其上游挂了同样不可用）。

[整理者注] board4 列依据 board4 书面自述整理，已经 board4 本人实测校验（内核/OS/核数/内存/安装位置/HERMES_HOME/版本/默认模型逐项核对一致）；board3 列为本机实测记录。
