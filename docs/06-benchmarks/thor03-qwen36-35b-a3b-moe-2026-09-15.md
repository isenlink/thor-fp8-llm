# Qwen3.6-35B-A3B 在 Thor03 实测报告

> **线路定位**：本文档属 **Q4_K_M MoE 实测线**（与仓库名指向的 FP8/NVFP4 主线不同题，曾在独立分支上评审，2026-09-25 经维护者确认并入 `main`）。同族部署配置见 `docs/05-system-tuning/llama-server-config.md`。

> **One-liner**: A 35B-total / ~3B-active MoE at Q4_K_M (21.1 GiB) runs at **739.98 pp512 / 40.24 tg128 tok/s** on a 14-SM DRIVE Thor board — dense-4B-class speed with 9× the parameters; GQA is extremely asymmetric (2 KV heads) so 256K of f16 KV costs only 20 GB.


**日期**：2026-09-15
**板卡**：Thor03（板卡序列号略），p3960/tegra264，DriveOS 7.0.3，风冷
**算力**：sm_101（compute capability 10.1，CUDA 12.8）— cudaDeviceGetAttribute 实测
**内存**：60G 统一内存（46G 大页池 = GPU 可见 47104 MiB）

## 模型
- 文件：`Qwen3.6-35B-A3B-UD-Q4_K_M.gguf`
- 来源：内网模型库 SMB 共享（路径略），unsloth UD 量化
- 大小：21.10 GiB（22663387424 bytes，与源 MD5 大小一致）
- 架构：MoE 35B 总参 / ~3B 激活，40 层，16 attn heads / **2 KV heads**，head_dim 256
- 多模态：图文输入（image-text-to-text），mmproj 可用

## 环境
- llama.cpp 二进制：x86 主机交叉编译 → ARM64 + CUDA(sm_101)
- 编译选项：GGML_CUDA=ON, CUDA_ARCH=101a, GGML_CUDA_FA=ON, GRAPHS=ON, F16=ON
- 运行参数：`-ngl 99 -fa on`

## 实测结果（llama-bench，-r 3）

| 测试 | 吞吐 | 说明 |
|---|---|---|
| pp512 | **739.98 ± 11.01 t/s** | 提示处理 |
| pp2048 | **731.91 ± 3.14 t/s** | 长提示 |
| tg128 | **40.24 ± 0.07 t/s** | 生成 |
| tg512 | **40.25 ± 0.01 t/s** | 长序列生成 |

## 关键结论

1. **生成 40.25 t/s** — 达到 4B 稠密模型同等速度，但模型容量大 9 倍
   （对比：Qwen3-4B = 40.2 t/s；Qwen3.8-27B NVFP4 = 26.48 t/s）
2. **Prompt 处理 740 t/s** — pp512 与 pp2048 几乎无衰减，上下文扩展良好
3. **MoE 架构红利兑现** — 激活仅 ~3B，速度接近小模型；35B 总参提供大模型知识量
4. **46G 大页池充足** — 21.1G 权重 + KV，用后自动释放归还池
5. **温度**：测试峰值 71°C（风冷阈值 75 预警/85 严重），短测安全
